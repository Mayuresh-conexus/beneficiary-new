# Beneficiary Biometric Enrollment & Verification Guide

This guide explains how to handle fingerprint data for **beneficiaries** within the Flutter app and how it syncs with the Laravel backend.

## 1. Data Type: Template vs. Image
**CRITICAL**: We do **not** store raw fingerprint images (`.jpg`, `.png`).
- We store a **Biometric Template**. This is a mathematical string (usually Base64 or Hex) representing the fingerprint's unique points.
- This technique is used for security, privacy, and fast matching.

## 2. Backend Fields
Our database and API use the following fields for every beneficiary:
- `biometric_template`: The string/code generated by the scanner.
- `biometric_device`: The name/model of the scanning hardware used.
- `biometric_enrolled_at`: Automatically set by the server when a template is provided.

---

## 3. Workflow

### A. Enrollment (Creating a Beneficiary)
When a volunteer registers a new person:
1. Use the fingerprint scanner (Native or External) to capture the fingerprint.
2. The scanner's SDK should provide a **minutiae template string**.
3. Send this string in the registration payload.

**Endpoint**: `POST /api/v1/beneficiaries`  
**Payload Snippet**:
```json
{
  "first_name": "John",
  "last_name": "Doe",
  "government_id": "ID-998877",
  "assigned_project_id": 1,
  "biometric_template": "BASE64_STRING_GENERATED_BY_SCANNER",
  "biometric_device": "Samsung_S23_Native_Scanner"
}
```

### B. Verification (During Distribution)
When a beneficiary comes to collect items:
1. App fetches the stored template: `GET /api/v1/beneficiary/{id}/biometric`.
2. App triggers a new scan on the spot.
3. Use the Scanner SDK to compare the **New Scan** vs **Fetched Template**.
4. If they match locally on the phone, tell the server verification was successful.

**Verification Log Endpoint**: `POST /api/v1/beneficiary/{id}/verify-biometric`  
*(No payload needed, just the ID in the URL to log the success for auditing).*

---

## 4. Why this approach?
1. **Speed**: Matching two strings is instant.
2. **Offline Ready**: You can download templates for a project and verify people even if there is NO internet at the distribution site.
3. **Security**: Templates cannot be reversed to steal a person's actual fingerprint image.
